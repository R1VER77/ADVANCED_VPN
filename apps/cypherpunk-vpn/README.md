# cypherpunk_vpn desktop application

Linux frontend in Vue 3, TypeScript and Tauri 2. The ordinary-user app talks to
`org.cypherpunk_vpn.Controller1` on the system bus. The root controller owns
networking, enrollment and hardware access. Cloud sign-ins and the operator's vault stay
with the user helper `avpn-desktop` (`tools/desktop_setup.py`), which the app runs with
fixed arguments only. This implementation remains under validation; creating new servers
from the app and real participant sessions are incomplete.

## Install

The release's native package carries this app and the controller:

```sh
sudo apt install ./cypherpunk-vpn_*_amd64.deb
```

Then open **Cypherpunk VPN** from the application menu and choose *Start setup*. Installing
enables and starts nothing.

## Build and run

Use Node 22.23.5 and the committed npm and Cargo lockfiles. Linux native builds
require the Tauri WebKitGTK 4.1 development dependencies.

```sh
npm ci --ignore-scripts
npm run build
npx tauri build --no-bundle
```

Install the matching verified controller package separately. Run the desktop app
as your ordinary desktop user. A browser preview cannot access the system broker
and correctly shows status as unavailable. Production never falls back to a mock.

For the separate simulated prototype:

```sh
npm run dev:demo
npm run build:demo
```

`demo.html`, `DemoApp.vue` and `controller/mock.ts` are excluded from the production
entry. The simulated PIN dialog belongs only to that demo. Production accepts no
PIN, passphrase, cloud token, shell command or arbitrary privileged file path.

## Current behavior

- One setup checklist (*Start setup*): security key and its access, the key's distribution
  software (upgrades only on request), this device's keys, cloud providers in a randomly
  named profile, the route (hops and jurisdictions) built on your recorded servers, and
  connect. Steps that need no decision run by themselves; the system prompts still ask.
- Provider list with shipped logos and dated prices (`src/controller/providers.json`,
  generated by `tools/providers.py --generate`); nothing is fetched.
- Fresh protection evidence and an explicit applications/whole-device scope.
  Unavailable or contradictory evidence displays status unknown.
- Caller-bound, expiring, one-use plans. Native administrator authentication repeats
  the stored summary, effects and digest outside the WebView. Hardware PINs remain
  in the trusted native/device prompt. Unlocking retains traffic protection.
- Offline Natural Earth map, original project logo and locally bundled assets.
  Existing signed profiles do not contain geographic coordinates; production leaves
  the map unlocated rather than inventing provider or region labels.
- IVPN-inspired split layout, black/white/gray palette, keyboard focus and reduced-motion
  support. No IVPN source or artwork was imported. See asset provenance files.

The repository LICENSE governs this component. The original standalone prototype
was preserved before import; `PROTOTYPE_ORIGIN.json` records its source hashes.

## Validation status

Production and demo web builds and native Rust checking/Clippy have passed locally.
The [native WebKit smoke](../../docs/evidence/NATIVE_GUI_20261118.json) also passed
with embedded production assets and an absent controller: status stays unknown,
no mock appears, and a 420-pixel window has no horizontal overflow. See the
[desktop](../../docs/evidence/gui/native-unknown-desktop-20261118.png) and
[narrow](../../docs/evidence/gui/native-unknown-narrow-20261118.png) captures.
This is a debug native build on a headless software display. Real D-Bus boundary
checks separately passed in Debian guests with disposable authorization rules.
These checks do not qualify packaged GUI installation, a native Polkit authentication
agent, complete owner setup or usability with five new participants.

Reproduce the rendering smoke on a disposable Linux host without the controller
installed or running (requires Xvfb, xauth, xdotool, ImageMagick, dbus-run-session
and busctl):

```sh
npm run build
cargo build --manifest-path src-tauri/Cargo.toml --locked --features tauri/custom-protocol
xvfb-run -a -s '-screen 0 1200x900x24 -nolisten tcp' dbus-run-session -- \
  node scripts/native-smoke.mjs src-tauri/target/debug/cypherpunk-vpn-gui NEW_OUTPUT_DIRECTORY
```

The smoke refuses an active or activatable controller, uses fresh application data,
waits for actual DOM and paint readiness, and opens a temporary loopback WebKit
inspector only for this test. It performs no privileged action or device operation.
The local build-tool dependency uses a vendored picomatch fork that rejects repeated
extglobs before regex construction. Its adversarial test includes a guard-removed
mutant; see `vendor/picomatch/CYPHERPUNK_GUARD.md`. This mitigation is separate from
an upstream fix or a claim of general glob-parser safety.

See `CONTROLLER_CONTRACT.md` and the main implementation progress document.
