# Security and code-quality audit — November 2026

Scope: all Rust (`src/`), Python (`tools/`), systemd units (`deploy/`) and CI.
Method: automated tools first (clippy pedantic, `cargo audit`, ruff with the
bandit-derived `S` rules, bugbear and pyflakes, `pip-audit` against the hash lock),
then a manual review of every privileged operation. Each finding was reproduced by a
test before it was fixed; security fixes were also mutation-checked (reverting the
fix makes the test fail).

## Findings and fixes

| # | Severity | Finding | Fix | Test |
|---|---|---|---|---|
| 1 | **High** | Privilege escalation. Root published runtime files into a directory the unprivileged service UID can write, then called path-based `chmod`/`chown` after the rename. A compromised data-plane process could swap the file for a symlink and redirect root's `chown` to any file (for example `/etc/shadow`). Certificate rotation re-armed this every 6 hours. | Create with `O_EXCL\|O_NOFOLLOW`, set mode and owner through the descriptor (`fchmod`, `fchown`), then rename. The path is never touched afterwards. | `RootFileHandoffTests` simulates the symlink race; it failed before the fix. |
| 2 | Medium | `cryptography` 49.0.0: PYSEC-2026-3552 / CVE-2026-69247 (Bleichenbacher oracle in PKCS#7 `EnvelopedData` decryption). Not reachable: no PKCS#7 or RSA use. | Upgraded to 50.0.0 (hash-locked); verified on Python 3.10 and 3.12. | `pip-audit` in CI. |
| 3 | Low | Root-run commands (`ip`, `nft`, `mount`, `systemd-creds`, `useradd`, …) were resolved through `$PATH`. | `sysexec.trusted_exe()` resolves only inside `/usr/sbin`, `/usr/bin`, `/sbin` and `/bin`, and requires a root-owned binary that isn't group- or world-writable. It is standard library only, so the installer can use it. | `TrustedExecutableTests` (PATH hijack ignored, bad names refused). |
| 4 | Low | TUN setup did not check `F_GETFL`'s error before `F_SETFL`. | Checked. | Clippy and the existing TUN tests. |
| 5 | Info | Two DNS length casts were implicit (already bounded). | `u16::try_from`. | — |
| 6 | Info | Late-binding closures in `preexec_fn` (correct only because `Popen` runs them synchronously). | Explicit `functools.partial`. | — |

| 8 | Practice | Dense, semicolon-chained one-line Python made review hard. Unused imports and variables. | Formatted with `ruff format`; a project `ruff.toml`; CI enforces format and lint. | CI. |

### Second pass: the command line, cloud setup and upstream entry

Found while building and behaviourally testing `avpn`, `avpn cloud` and upstream
entry. Each finding has a test that fails without the fix (mutation-checked).

| # | Severity | Finding | Fix | Test |
|---|---|---|---|---|
| 9 | Medium | Read-only queries (`status`, `info`, `hops`) created `/run/advanced-vpn/state-*` as a side effect. As a normal user they failed; as root they left state behind. | `runtime_dir(create=False)` for queries; an existing directory is still checked. | `test_read_only_queries_create_no_runtime_state` |
| 10 | Medium | The first draft of the installed launchers used `python -I`. On Python 3.11+ that drops the script directory from `sys.path`, so the installed controller could not import its own modules. Caught by running it, before it shipped. | `-E -s`: no `PYTHON*` variables, no user site directory; the root-owned tools directory stays importable. | Staged-package run |
| 11 | Low | `doctor` crashed when `nft`, `systemctl` or `curl` was missing, which is exactly when it is needed. | Missing tools are reported as failed checks. | `test_doctor_reports_missing_tools_instead_of_crashing` |
| 12 | Low | Operator-precedence bug: the resolver-isolation detail could never say "none present". | Parenthesised. | `test_doctor_reports_when_no_resolver_socket_exists` |
| 13 | Low | Controller refusals reported only an exception type, so users could not tell why something was refused. | `RuntimeError`/`ValueError` (the controller's own refusals) carry their message. Other exception types still print only their name, so library text (paths, arguments) is never echoed. | `test_refusals_carry_the_controllers_reason` |
| 14 | Design | `avpn` honours `AVPN_CONTROLLER` (and `AVPN_SYSTEMCTL`, `AVPN_CLOUD`) for development. As root, that would let `sudo -E` run another program as root. | Root ignores the controller and systemctl overrides and requires root-owned, write-protected executables. `avpn cloud` refuses root outright. | `test_root_ignores_the_controller_override`, `test_root_is_refused` |

Cloud setup guards: tag-scoped teardown; a refusal for tagged instances not named
`avpn-*`; IMDSv2 required; the one-Region rule; single public IPv4 sources only. Each
is mutation-checked in `test_cloud.py` (five mutations, all caught). Upstream entry's
guard is mutation-checked in the namespace lab: without it, the tunnel silently
re-forms over the direct path when the upstream drops.

Found earlier in this release cycle, and covered by regression tests:
- the app-mode DNS leak through host resolver sockets;
- a missing `CAP_KILL`, and `chmod` after `chown` without `CAP_FOWNER`;
- the systemd-resolved DNS failure in whole-device mode;
- the desktop PIN prompt diverted to systemd;
- systemd-creds silently skipping the TPM;
- a public listener bound behind NAT;
- the per-session rate bound that capped throughput;
- budget leaks.

## Reviewed, no change needed (now guarded)

- **nftables rule text:** every profile value that reaches it (endpoints, ports, DNS
  address, carrier keys) is strictly validated. Hostile values are refused
  (`test_profile_values_that_reach_firewall_text_are_strictly_validated`).
- **Integer casts** flagged by clippy (`cast_possible_truncation`/`wrap`/`sign_loss`):
  all bounded by earlier checks.
- **All 19 `unsafe` blocks:** documented `SAFETY` comments; descriptor ownership and
  seal checks are correct.
- **Subprocesses:** argument lists only, no shell, timeouts.
- **Enrollment parsing:** size, member and name limits; signatures before any
  extraction.
- **Signals:** PID-reuse-safe (start-time identity check).
- **CI:** actions pinned by SHA, read-only permissions.

## Not covered by this audit
- An independent external review. You can run `/code-review ultra` on the branch.
- Statistical traffic-analysis resistance.
- TEE attestation.
